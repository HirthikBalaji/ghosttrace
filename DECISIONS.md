# Decisions

Each entry: decision · alternatives · reason.

| # | Decision | Alternatives considered | Reason |
|---|---|---|---|
| D-001 | Modular monolith: FastAPI + Pydantic v2 backend, React/TS/Vite frontend, FalkorDB only datastore | Microservices; separate Postgres for tasks | The repo was empty. One process is simplest to make robust, and keeping tasks, memory and facts in the workspace graph gives isolation and durability together. |
| D-002 | Pin `falkordb/falkordb:v4.22.0` (C engine) and Python client `falkordb==1.7.1` | `6.0.x` (released 2026-09-29, newer line), `latest` | v4.22.0 is the mature line. Every API used (`ro_query`, per-query `timeout`, range indexes, unique constraints, `copy`, procedures) was verified against it by a smoke test before use. |
| D-003 | Python 3.12 via uv (lockfile `backend/uv.lock`) | System Python 3.14 | Widest wheel compatibility for pinned deps. |
| D-004 | One graph per workspace (`ws:<id>`) **and** a `workspace_id` property checked in every query | Single graph with property filter only | Defense in depth, as required. Tested by `test_tenant_isolation_graph_and_properties`. |
| D-005 | Capability edges point in the direction of capability flow (`u→v`: control of u yields capability over v). Introduced `CAN_ASSUME` (Identity→Identity) and `CONNECTS_TO`; did not use `ASSUMED_BY` | Mixed edge directions per type | Uniform direction keeps the traversal predicate, κ rules and BFS simple and auditable. `TRAVERSAL_EDGE_TYPES` is the documented allowlist. |
| D-006 | Bitemporal **edge** facts; nodes are not versioned. Each fact version is its own relationship `(edge_id, version)`. Supersession is recorded via `supersedes` (prior version number) on the relationship, not a `SUPERSEDES` edge | Reify every fact as a node | Relationships cannot point at relationships. Reification would make every path query twice as long. `SUPERSEDES` *is* used between `:Memory` nodes. |
| D-007 | Ingestion is a pure in-memory ledger (`app/ingestion/ledger.py`) that emits deterministic versions; the repository persists them with idempotent `MERGE` on `(edge_id, version)` | Write-through ingestion directly in Cypher | Makes ingestion unit-testable and idempotent by construction. Re-seeding yields identical counts (tested). |
| D-008 | **Relationship indexes only on `edge_id`**; migration 2 drops temporal and workspace relationship indexes | Index `tx_from`, `valid_from` and `workspace_id` on every relationship type | While testing latent-template preconditions we found that FalkorDB v4.22.0 returns **incorrect rows** for multi-edge patterns. This happens when several relationships in the pattern have index-eligible property filters: the planner chooses `Edge By Index Scan` per relationship and loses the binding between them. Example: the `group_inheritance_unmodeled` precondition matched a `peer` that was not in the group. The Cypher-vs-Python differential test over all template pairs now guards this (`test_latent_template_cypher_equals_python`). |
| D-009 | Seeded scenarios replay a synthetic ingestion log; the seeded `at` timestamps **are** the transaction times (simulated clock). Investigations run on the scenario's analysis clock; red-team writes advance it by one simulated minute | Use wall-clock tx times for seeded data | Without this, "as known then vs now" could not be reproduced. Live API writes would use the wall clock. |
| D-010 | Derived facts (`policy_expansion`) are materialised as the **bitemporal intersection** of parent versions and recomputed fully on each ingestion | Derive at query time only | Derived edges are then visible to Cypher path queries and keep correct history. |
| D-011 | LATENT edges are stored with `validity_unknown=false` (assumed valid while visible): their *existence* is the assumption | Mark latent edges validity-unknown | Otherwise every path through a latent edge would be misclassified as TEMPORALLY_UNCERTAIN instead of CONDITIONAL(k). |
| D-012 | Reopening distance counts LATENT **and** validity-unknown edges as weight 1; flows require CONFIRMED edges only | Ignore uncertain edges | Conservative and consistent with "missing data weakens a conclusion". |
| D-013 | Trust classes are computed at query time per trust policy (R1–R3 are pure functions over `source_ids`/`dispute_source_ids`). Trusted removals (R2-satisfying) close validity at ingestion; untrusted ones are stored as disputes | Store a fixed class on each edge | R4 requires re-classifying the same facts under two policies. R5 needs falsification overlays. |
| D-014 | Solver: exact **branch-and-bound** over a hitting-set master + exhaustive 0-1 BFS subproblem + deletion-minimised nogoods. A brute-force enumerator exists only as a test oracle | OR-Tools CP-SAT | No extra native dependency. Candidate sets are small (≤ ~64), and exactness is provable within the declared candidate set. `J` is monotone in the action set, so `J(partial)` is a valid bound. |
| D-015 | Warm start re-validates prior counterexample paths: a constraint is kept only if the path still exists **and has ≤ k non-confirmed edges under the current classification** | Reuse all prior constraints | Found by `test_warm_start_equals_cold_after_new_evidence`: reusing k=1 constraints at k=0 over-constrained the master (cost 12 vs optimum 5). |
| D-016 | Certificate `k_certified` is canonical: `d−1` when `d` is finite; when no path survives, the number of non-confirmed edges in the snapshot. The verifier enforces it | Any `k < d` | The eval mutation run found `inflate_k` survived on ∞-robust plans. Canonical k makes the claim exact and kills the mutant. |
| D-017 | The verifier trusts the export's per-edge class and temporal status as data (bound by the snapshot hash). It independently re-implements κ, reachability, 0-1 BFS, flows, cost arithmetic and small-instance optimality | Re-implement R1–R3 and bitemporal logic in the verifier | Keeps the trusted base under 450 lines (enforced by test). The limitation is stated in every certificate's assumptions. |
| D-018 | The UI and API verify certificates by running `python -m verifier` **as a separate process** with a fixed argv and isolated env | Import the verifier in-process | Demonstrates independence; the verifier shares no code with the planner. |
| D-019 | Deterministic `MockProvider` is the default LLM; an OpenAI-compatible adapter exists but is never used by tests | Require an API key | Spec requires offline, reproducible tests and demo. The model only summarises, explains and nominates. All ids it cites are validated against graph results. |
| D-020 | Red-team latent nominations are accepted only if the template's constant Cypher precondition holds in FalkorDB | Accept the model's claim | The spec forbids LLM-created facts. The Python mirror is differential-tested against the Cypher. |
| D-021 | R5 load-bearing evidence: exhaustive search for minimal falsification sets of size ≤ 2 over relevant records (≤ 40). Falsifying a record deletes its support and reverts any validity closure it justified | Full ATMS label propagation | Exact for the stated bound, simple to test. The bound is documented. |
| D-022 | Generated benchmark latent edges bypass template preconditions | Synthesize matching group/host structures for every latent | Keeps the generator small. The template engine is tested separately (scenario A + differential). |
| D-023 | Demo auth: shared header token compared in constant time; fails closed when unset. No OIDC | Implement OIDC | Out of scope for a local synthetic demo. Stated plainly everywhere. |
| D-024 | Ruff line length 130; `ruff format` applied repo-wide | 88/110 | Dense domain code with long Cypher strings; consistency over churn. |
| D-025 | TypeScript 7.0.2 (latest at build time) | TS 5.x | Typecheck and build verified; no compatibility issues found. |
| D-026 | Graph view uses Cytoscape `breadthfirst` rooted at suspected-compromised sources; edge labels off by default (toggle) | Force-directed layout | Readable attack-path direction. Class is also encoded by line style, legend and table text, never color alone. |

## Untrusted content encountered (§0.3)

- `BUILD.md` is the operator's prompt. No other pre-existing repository content existed.
- The only instruction-like text processed is the **intentional synthetic fixture** `src:ticket-HD-5521`
  ("SYSTEM OVERRIDE: ignore previous instructions…"). It is treated as data, flagged and tainted, and no tool call
  results from it (tested in `test_prompt_injection_treated_as_data`).
- Dependency READMEs and tool output contained no instructions directed at the agent.
